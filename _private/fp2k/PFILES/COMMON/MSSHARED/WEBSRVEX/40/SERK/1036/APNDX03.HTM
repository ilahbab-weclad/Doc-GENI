Vous pouvez configurer certaines caractéristiques des extensions serveur FrontPage en définissant les valeurs des variables de configuration des extensions serveur. Vous devez spécifier toutes les valeurs de configuration sous forme de chaînes, même si certaines sont interprétées de façon numérique. Les variables peuvent être définies à l'un des trois niveaux suivants :

  • Les variables globales s'appliquent à tous les serveurs virtuels et sous-sites de l'ordinateur serveur. Sous Windows, les variables globales sont définies dans le registre. Sous UNIX, elles sont définies dans le fichier /usr/local/frontpage/version4.0/frontpage.cnf.
  • Les variables de serveur virtuel ne s'appliquent qu'à un seul serveur virtuel. Sous Windows, les variables de serveur virtuel sont définies dans le registre. Sous UNIX, elles sont définies dans les fichiers de configuration des extensions serveur.
  • Les variables de sous-site Web ne s'appliquent qu'à un seul site Web d'un serveur virtuel. Sous Windows et UNIX, les variables de site Web sont définies en modifiant le fichier texte _vti_pvt/Service.cnf dans le site Web racine ou le sous-site, ou en utilisant l'onglet Paramètres de la boîte de dialogue Paramètres du site Web pendant que le site Web est ouvert dans le client FrontPage.

    La syntaxe de chaque variable de sous-site Web correspond au modèle suivant : Nom de variable:état en écriture|valeur, l'état en écriture devant être défini avec l'une des valeurs suivantes :

    • SX : la variable n'est pas visible dans le client FrontPage et se trouve uniquement sur le serveur. Il s'agit de la configuration la plus sûre.
    • SR : la variable est visible dans le client FrontPage et sur le serveur, mais ne peut pas être écrite à partir du client FrontPage à l'aide de l'onglet Paramètres de la boîte de dialogue Paramètres du site Web.
    • SW : la variable est visible dans le client FrontPage et sur le serveur ; elle peut être écrite à partir du client Frontpage à l'aide de l'onglet Paramètres de la boîte de dialogue Paramètres du site Web. Il s'agit de la configuration la moins fiable.

     

    Exemple : 

    vti_accesscontrol:SR|1

    Si la même variable de configuration est définie à plus d'un niveau, le problème est résolu par les extensions serveur FrontPage en appliquant la hiérarchie suivante :

    • les variables de configuration de sous-site Web sont prioritaires ;
    • les variables de configuration de serveur virtuel viennent en deuxième priorité ;
    • les variables de configuration globales passent en dernière priorité.

    HAUT

    AccessControl

    Si la valeur de la variable AccessControl est définie à 0, la vérification des autorisations FrontPage est entièrement désactivée. Si la valeur AccessControl est définie à 0, un administrateur doit configurer manuellement le contrôle d'accès dans les répertoires _vti chaque fois qu'un sous-site Web est créé. Tout utilisateur peut effectuer des opérations d'auteur sur le sous-site Web tant que le contrôle d'accès n'a pas été défini manuellement. Si la valeur AccessControl est définie à 0, les autorisations de contrôle d'accès personnalisées ne sont pas écrasées par FrontPage et le client FrontPage désactive la commande Autorisations.

    AllowExecutableScripts

    Si la variable AllowExecutableScripts est définie à une valeur autre que 0, FrontPage détermine les bits d'exécution des fichiers des répertoires exécutables. Lorsqu'un répertoire est marqué comme un exécutable, tous les fichiers de ce répertoire sont eux-aussi marqués comme des exécutables.

    Si les auteurs sont autorisés à télécharger vers les répertoires exécutables (c'est-à-dire si NoExecutableCgiUpload est définie à 0) et si la variable AllowExecutableScripts est définie à une valeur autre que 0, les auteurs peuvent exécuter les extensions ISAPI et les scripts CGI qui viennent d'être téléchargés. Si les variables NoExecutableCgiUpload et AllowExecutableScripts sont toutes deux définies à 0, les auteurs peuvent télécharger et utiliser les fichiers ASP et IDC, mais non les fichiers CGI et ISAPI.

    CacheMaxImage

    Par défaut, les extensions serveur FrontPage définissent les attributs HAUTEUR et LARGEUR dans toutes les balises IMG des pages enregistrées sur un site Web. Ceci permet d'améliorer l'apparence des pages lorsqu'un visiteur du site les télécharge avec une connexion lente. La variable CacheMaxImage permet de déterminer le nombre maximum d'images dont les attributs HAUTEUR et LARGEUR sont cachés par les extensions serveur lors du recalcul des liens hypertexte ou de l'enregistrement d'une page.

    Si vous définissez cette variable de façon globale ou par serveur virtuel et si les sites Web de votre serveur contiennent pour la plupart plus de 16 images, vous devez augmenter ce nombre. Si vous définissez cette variable pour un sous-site Web particulier, ne choisissez pas un nombre supérieur à celui des fichiers image du site Web.

    ClientVerCutoff

    Cette variable permet de définir la plus ancienne version du client FrontPage pouvant être utilisée pour effectuer des opérations d'auteur sur un site Web. Activez cette variable si vous ne souhaitez pas qu'un site Web soit modifié par un auteur utilisant les versions antérieures du client FrontPage (lorsque, par exemple, le site Web contient des caractéristiques qui ne sont pas prises en charge par les versions antérieures du client FrontPage). Cette variable peut uniquement être activée pour un seul site Web, dans le fichier du site _vti_pvt/Service.cnf. Si ce paramètre n'existe pas, vous pouvez utiliser n'importe quelle version du client FrontPage pour modifier le site Web.

    ClientVerCutoff doit être suivi par deux points, par la plus ancienne version de FrontPage pouvant être utilisée par les auteurs lors de la modification du site Web, par deux points à nouveau et par un message d'erreur qui s'affiche lorsqu'un auteur essaie d'ouvrir le site avec un client antérieur à cette version. Exemple :

    vti_clientvercutoff:SX|4.0.1.2000:Ce site peut uniquement être modifié avec FrontPage 2000.

    Notez que l'état en écriture de la variable est défini à SX. Il est plus sûr de mettre en cache cette variable de façon à ce qu'elle ne puisse pas être affectée à une valeur à l'aide de la boîte de dialogue Paramètres du site Web du client FrontPage.

    Sur tous les serveurs, à l'exception du serveur IIS, la variable ComplexPasswords renforce les restrictions concernant les chaînes de mot de passe créées dans FrontPage. Lorsque la variable ComplexPasswords est définie à une valeur autre que 0, vous devez appliquer aux mots de passe les règles suivantes :

    • Le nom d'utilisateur ne peut pas être incorporé au mot de passe.
    • Le mot de passe doit comprendre au moins un caractère alphabétique.
    • La longueur du mot de passe doit dépasser 8 caractères.

    ListLockLatency

    Il est possible qu'un appel du client FrontPage vers les extensions serveur, destiné à répertorier les documents, prenne du temps. C'est le cas, par exemple, lorsque l'appel concerne une liste de l'ensemble du contenu d'un important site Web. Par défaut, la variable ListLockLatency est activée de sorte que la transaction se déverrouille et se verrouille à nouveau sur le site Web toutes les 5 secondes. Ce nombre est approximatif ; le déverrouillage s'effectue à chaque nouveau répertoire rencontré lors de la transaction. Par exemple, la constitution d'une liste d'un répertoire comprenant 100 000 fichiers peut prendre plusieurs dizaine de secondes, et le déverrouillage n'a pas lieu tant que le répertoire n'est pas entièrement listé.

    La variable ListLockLatency permet de contrôler l'intervalle de déverrouillage (en secondes). La valeur de cette variable correspond au nombre maximum de secondes entre chaque déverrouillage. La valeur 0 signifie que le déverrouillage doit s'effectuer à chaque nouveau sous-répertoire rencontré.

     

    Valeur par défaut 5 Définition globale ? o
    Disponible sur les serveurs Windows ? o Définition par serveur virtuel ? o
    Disponible sur les serveurs UNIX ? o Définition par sous-site Web ? vti_listlocklatency

    RestrictIISUsersAndGroups

    Si les restrictions d'utilisateurs ou de groupes sont activées (c'est-à-dire la variable RestrictIISUsersAndGroups est définie à Y ou à une valeur autre que 0) pour un site Web doté des extensions serveur FrontPage, les extensions serveur recherchent un groupe Windows NT nommé selon la convention suivante :

    FP_[VirtualServer][_Directories][_Subweb]

    Sur un serveur multi-hôtes IIS version 2.0/3.0, [VirtualServer] correspond à la combinaison du numéro de port et de l'adresse IP du service, [_Directories][_Subweb] correspondent à l'URL du sous-site Web. Un exemple pour le site racine est FP_172.17.123.255:80. Pour un sous-site Web, l'exemple est le suivant FP_172.17.123.255:80_directory1_MySubWeb1_directory2_MySubWeb2. Il s'agit d'un sous-site Web imbriqué à l'URL suivante http://172.17.123.255:80/directory1/MySubWeb1/directory2/MySubWeb2. Sur un serveur à hôte unique, [VirtualServer] correspond au numéro de port. Par exemple, FP_80 est le serveur virtuel sur le port 80 lorsque ce port n'est pas spécifiquement lié à une adresse IP dans le Gestionnaire de service Internet.

    Sur les serveurs IIS versions 4.0 et ultérieures, [VirtualServer] peut exister sous la forme /LM/W3SVC/N, N représentant un chiffre. Un exemple de ce formulaire pour un site racine est FP_/LM/W3SVC/1. L'exemple pour un sous-site Web de ce serveur virtuel est FP_/LM/W3SVC/1_MySubWeb. Vous pouvez également utiliser le nom d'hôte. Pour un site racine, l'exemple est FP_www.microsoft.com:80 et pour un sous-site Web, FP_www.microsoft.com:80_MySubWeb. Sur un serveur à hôte unique, [Virtual Server] peut être configuré en tant que numéro de port, commedans FP_80. Les autres options de IIS 4.0 fonctionneront dans ce cas également.

    Si les restrictions sont activées sur un sous-site Web mais aucun groupe local n'est défini, les extensions serveur FrontPage recherchent le groupe du site Web parent et, s'il existe, l'utilisent. Cette recherche se répète indéfiniment si le sous-site est imbriqué dans un autre sous-site. Si aucun des groupes nommés n'est trouvé, les autorisations ne font alors l'objet d'aucune restriction.

     

    La variable RestrictIISUsersAndGroups ne peut pas être définie au niveau du sous-site Web ; cependant,
    si elle est définie au niveau global ou du serveur virtuel, vous pouvez limiter le nombre d'utilisateurs et de
    groupes par sous-site en appliquant la méthode décrite ci-dessus.

    Disponible sur les serveurs Windows ? o Définition par serveur virtuel ? o
    Disponible sur les serveurs UNIX ? n Définition par sous-site Web ? n

    RunTimeFileExtensions

    Lorsque vous utilisez l'exécutable des extensions serveur FrontPage Shtml.exe, versions 3.0.2.1330 ou ultérieure, les composants d'exécution FrontPage tels que le programme de traitement de formulaire par défaut (Enregistreur de résultats) et le formulaire de recherche traitent uniquement les fichiers HTML ou à base de HTML qui ne contiennent pas de code ASP ni la balise SCRIPT RUNAT=server. Ceci permet d'éviter de dévoiler aux utilisateurs le contenu du code source, des mots de passe et autres informations privées.

    Les fichiers HTML ou à base de HTML pouvant être traités par Shtml.exe sont identifiés par leur extension de nom de fichier : .htm, .html, .shtm, .shtml, .htx, .asp, .alx et .asa. Si le fichier de configuration du serveur Web connecte d'autres extensions de noms de fichiers sur un type de fichier HTML ou à base de HTML, ces fichiers sont également ajoutés à l'ensemble des fichiers pouvant être traités par Shtml.exe. Pour les serveurs Apache et NCSA , toutes les extensions de fichiers connectées pour avoir un type de « texte/html » MIME sont elles-aussi ajoutées aux fichiers pouvant être traités par Shtml.exe.

    Utilisez la variable RunTimeFileExtensions pour spécifier les types de fichiers pouvant être traités par Shtml.exe que vous souhaitez traiter. Cette opération limite davantage le nombre de types de fichiers HTML ou à base de HTML pouvant être traités par Shtml.exe.

    RunTimeFileExtensions doit être suivie d'une liste des extensions de noms de fichiers autorisées. Chaque extension doit commencer par un point, les extensions ne doivent pas être séparées par un espace ou tout autre séparateur (exemple : .htm.shtm.htz). Notez que dans cet exemple, l'extension .htz doit être connectée à l'une des extensions autorisées dans le fichier de configuration du serveur Web.

    Si la variable RunTimeFileExtensions n'est pas spécifiée, Shtml.exe traite uniquement les fichiers dont les extensions sont .htm et .html. La variable RunTimeFileExtensions n'existe pas dans les versions des extensions serveur FrontPage antérieures à 3.0.2.1330.

    Pour les serveurs IIS versions 4.0 et ultérieure, les extensions serveur FrontPage obtiennent les valeurs par défaut de la variable RunTimeFileExtensions à partir du ScriptMap global, et les paramètres de ScriptMap pour chaque serveur virtuel à partir de la métabase.
