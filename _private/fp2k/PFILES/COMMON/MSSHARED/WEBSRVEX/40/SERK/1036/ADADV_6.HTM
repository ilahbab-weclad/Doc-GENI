Installer Microsoft Visual SourceSafe pour une utilisation avec FrontPage

L'intégration à Microsoft Visual SourceSafe version 5.0 ou ultérieure est disponible sur tous les serveurs Web gérés par FrontPage sous Microsoft® Windows NT® Server version 4.0 ou ultérieure, Windows NT Workstation version 4.0 ou ultérieure, et Windows® 95/98.

Sous Windows 95, le Serveur Web personnel Microsoft nécessite la mise à jour Windows 95 de DCOM (Distributed Component Object Model) pour fonctionner avec Visual SourceSafe. Pour plus d'informations, reportez-vous à http://www.microsoft.com/com/dcom/dcom1_2/default.htm (site en anglais).

HAUT

Activation de l'intégration de SourceSafe

Pour utiliser Visual SourceSafe avec FrontPage, vous devez choisir Activer l'intégration SourceSafe lors de l'installation de Visual SourceSafe :

  1. Exécutez le programme d'installation de Visual SourceSafe, Setup.exe, à partir du CD Visual SourceSafe.
  2. Sélectionnez l'option d'installation Personnalisée.
  3. Dans la boîte de dialogue Personnalisée de Visual SourceSafe, cliquez sur la case à cocher Activer l'intégration SourceSafe.
  4. Cliquez sur Continuer.

Votre configuration Visual SourceSafe

Vous pouvez stocker votre base de données Visual SourceSafe sur le même ordinateur que celui du serveur Web (une base de données locale) ou sur un ordinateur dIfférent (une base de données distante). Si la base de données se trouve sur le même ordinateur que le serveur Web mais qu'elle n'est accessible qu'en utilisant les chemins UNC, elle est considérée comme étant distante. Par exemple, la base de données suivante est distante car le fichier Srcsafe.ini sur l'ordinateur IIS comporte l'une des lignes suivantes :

Data_Path = X:\vssdata

Data_Path = \\IIS-Machine\vssdata

Vous pouvez également consulter le registre pour savoir si la base est accessible par des chemins UNC ou des chemin mappés.

Vous devez noter votre type de configuration, car si vous utilisez une base de données distante, vous devrez effectuer quelques étapes supplémentaires.
HAUT

Fichier INI Visual SourceSafe

Les extensions serveur FrontPage doivent trouver un fichier Srcsafe.ini pour effectuer des opérations Visual SourceSafe via une automatisation OLE. Visual SourceSafe 5.0 utilise généralement la clé de registre HKEY_LOCAL_MACHINE\Software\Microsoft\SourceSafe\SCCServerPath. Bien que cette clé pointe vers le fichier Ssscc.dll dans le répertoire VSS\Win32, les extensions serveur FrontPage utilisent le fichier Srcsafe.ini dans le répertoire VSS. Visual SourceSafe 6.0 utilise normalement le fichier Srcsafe.ini lors de l'installation de Visual SourceSafe sur le serveur Web.

Les procédures suivantes supposent que le serveur Web est un serveur IIS s'exécutant sous Windows NT 4.0, que la base de données Visual SourceSafe est également sous Windows NT 4.0 et que tous deux se trouvent sur des partitions NTFS.

Autorisations pour les répertoires Visual SourceSafe

Vous devez définir des autorisations dans la structure de répertoires Visual SourceSafe et pour les fichiers.

  1. Sur l'ordinateur sur lequel se trouve la base de données Visual SourceSafe, configurez les autorisations de sécurité et de partage pour les répertoires Visual SourceSafe :
    • Pour connaître les autorisations des répertoires, dans l'Explorateur Windows NT, cliquez avec le bouton droit de la souris, puis cliquez sur Propriétés dans le menu contextuel, cliquez sur l'onglet Sécurité, puis sur Autorisations.

      Pour connaître les autorisations partagées, dans l'explorateur Windows NT, cliquez avec le bouton droit de la souris sur le répertoire partagé, cliquez sur Propriétés dans le menu contextuel, puis sur l'onglet Partage, et cliquez sur Autorisations.

    • Utiliser la commande Modifier les autorisations pour tous les comptes de connexion Visual SourceSafe pour tous les fichiers et sous-répertoires sous le répertoire d'installation du serveur Visual SourceSafe (y compris le répertoire de données Visual SourceSafe s'il se trouve à un emplacement différent).

      On suppose que les comptes Administrateurs et Système auront le Contrôle total sur toute la hiérarchie Visual SourceSafe. Bien que des restrictions plus strictes soient possibles, les fonctionnalités de Visual SourceSafe peuvent moins bien fonctionner avec.

  2. Octroyez au moins les droits en lecture pour tous les comptes de connexion Visual SourceSafe pour les fichiers suivants :
    • Srcsafe.ini
    • Um.dat
    • Users.txt

    Octroyez au moins les droits en lecture et en écriture à tous les comptes de connexion Visual SourceSafe pour les fichiers et répertoires suivants :

    • Vss\Users\<logon account directory>\
    • Vss\Data\
    • Vss\Temp\
    • Rights.dat
    • Status.dat

Si vous utilisez une base de données distante Visual SourceSafe, vous devez effectuer les opérations suivantes.

Propriétés du Service WWW

Vous devez définir les propriétés du Service WWW sur le serveur Web.

  1. Dans le Gestionnaire des services Internet, ouvrez le dossier Internet Information Server, cliquez avec le bouton droit de la souris sur le serveur Web, puis cliquez sur Propriétés dans le menu contextuel.
  2. Dans Propriétés principales, cliquez sur Service WWW, puis sur Modifier.
  3. Cliquez sur l'onglet Sécurité du répertoire, puis sous Connexions anonymes et contrôle d'authentification, cliquez sur Modifier.
  4. Cochez la case De base (texte clair) mais ne sélectionnez pas la case Authentification Stimulation/Réponse de Windows NT .

 

L'authentification Stimulation/Réponse de Windows NT est également appelé NTLM. Comme cette option n'est pas sélectionnée, les utilisateurs doivent entrer leur noms d'utilisateur et leur mot de passe de domaine lorsqu'ils ouvrent un site Web. Utilisez le format NomDomaine\NomUtilisateur pour le nom d'utilisateur lorsque vous travaillez sur différents domaines.

Aucune authentification (accès anonyme autorisé) est facultatif.

Autorisations de comptes anonymes

Si vous utilisez un compte anonyme (Aucune authentification (accès anonyme autorisé) est sélectionné dans la procédure ci-dessus ), procédez comme suit sur l'ordinateur disposant de la base de données Visual SourceSafe :

  1. Dans Gest. des utilisateurs pour les domaines, dans le menu Utilisateur, cliquez sur Nouvel utilisateur pour ajouter le compte anonyme sur le serveur Web. Par exemple, si le compte anonyme sur le serveur Web est IUSR_WEBSRV, ajoutez cet utilisateur en tant que compte local.
  2. Donnez au compte le même mot de passe que celui qu'il possède sur le serveur Web.
  3. Cliquez sur OK.
  4. Sous Nom utilisateur, cliquez sur le compte anonyme.
  5. Dans le menu Stratégies, cliquez sur Droits de l'utilisateur.
  6. Dans la liste Droit, cliquez sur Nom d'accès local. Assurez-vous que le compte anonyme est répertorié dans la boîte

    Accorder à individuellement ou en tant que membre d'un des groupes, puis cliquez sur OK.
