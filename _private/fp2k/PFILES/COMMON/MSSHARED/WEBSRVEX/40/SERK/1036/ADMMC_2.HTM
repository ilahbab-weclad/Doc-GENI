HAUT

Extension d'un serveur virtuel avec les extensions serveur FrontPage

Une fois que vous avez créé un serveur virtuel, vous pouvez l'étendre avec les extensions serveur FrontPage qui le transforment en site Web racine. Pour qu'un serveur virtuel puisse être étendu, il faut que les extensions serveur aient déjà été installées sur l'ordinateur serveur.

  1. Dans l'arborescence de la console, cliquez sur le serveur virtuel que vous voulez étendre.
  2. Cliquez sur Tâches dans le menu contextuel, puis sur Configurer les extensions serveur.

    Si le serveur Web n'est pas de type IIS version  4.0 ou ultérieure, cliquez sur Nouveau dans le menu contextuel, puis sur Site Web.

  3. Suivez les étapes de l'Assistant Configuration des extensions serveur.

 

Pour doter un serveur virtuel de sous-sites, vous devez l'étendre, c'est à dire le transformer en site Web racine.

 

HAUT

Création d'un sous-site

Un sous-site est un sous-dossier du site Web racine ou d'un autre sous-site constituant un site FrontPage étendu complet. C'est une division logique du contenu d'un site Web complet.

Un sous-site permet de définir une autorisation d'administration, d'opérations d'auteur et de navigation distincte, de scinder le contenu d'un site en subdivisions logiques pour améliorer les performances, d'appliquer une apparence différente aux pages de chaque sous-site et de gérer facilement les liens hypertexte.

Vous pouvez seulement créer un sous-site sur un site Web racine ou un sous-site, ou sur un dossier du site Web racine ou du sous-site. Lorsque vous créez un sous-site, vous l'étendez avec les extensions serveur FrontPage en même temps. Le système crée automatiquement un dossier pour le sous-site.

  1. Dans l'arborescence de la console, cliquez avec le bouton droit de la souris sur le site (ou dossier) pour lequel vous voulez créer un sous-site.
  2. Cliquez sur Nouveau dans le menu contextuel, puis sur Site Web avec des extensions serveur.

    S'il ne s'agit pas d'un serveur Web IIS version 4.0 ou ultérieure, cliquez sur Nouveau dans le menu contextuel, puis sur Site Web.

  3. Suivez les étapes du Nouvel Assistant Sous-site Web.

Ajout d'un administrateur

Si vous avez oublié votre mot de passe ou si vous souhaitez qu'une autre personne puisse administrer un site, vous pouvez créer un administrateur.

  1. Dans l'arborescence de la console, cliquez avec le bouton droit de la souris sur le site auquel vous vouIez ajouter un administrateur.
  2. Cliquez sur Nouveau dans le menu contextuel, puis sur Administrateur des extensions serveur.

    S'il ne s'agit pas d'un serveur Web IIS version 4.0 ou ultérieure, cliquez sur Nouveau dans le menu contextuel, puis sur Administrateur.

  3. Dans la zone Nom d'utilisateur, indiquez un compte Windows NT à ajouter au site en tant qu'administrateur.

    S'il ne s'agit pas d'un serveur Web IIS version 4.0 ou ultérieure, entrez un nom d'utilisateur dans la zone Nom d'utilisateur et le même mot de passe dans les zones Mot de passe et Confirmation de mot de passe.

 

HAUT

Suppression des extensions serveur FrontPage sur un site Web racine et ses sous-sites

Il peut arriver que vous ou l'auteur d'un site décide qu'il n'est plus nécessaire qu'un site contienne les extensions serveur FrontPage. Dans ce cas, vous pouvez supprimer les extensions serveur sur le site Web racine et du même coup sur tous les sous-sites de ce dernier.

Lorsque vous supprimez les extensions serveur, toutes les fonctions du site prises en charge par les extensions serveur FrontPage, telles que le compteur d'accès et les programmes de gestion de formulaires électroniques ne fonctionneront plus. Le contenu du site par contre est inchangé. Seules les extensions serveur sont supprimées.

  1. Dans l'arborescence de la console, cliquez avec le bouton droit de la souris sur le site Web racine dont vous voulez supprimer les extensions serveur.
  2. Cliquez sur Tâches dans le menu contextuel, puis sur Supprimer les extensions serveur.

    Par défaut, les fichiers contenant des informations sur la structure du site, les thèmes, etc. ne sont pas supprimés, de façon à ce que vous puissiez recréer le site exactement tel qu'il est si vous décidez de l'étendre à nouveau par la suite. En revanche, si vous êtes certain de ne plus jamais avoir besoin des extensions serveur FrontPage sur ce site, désactivez la case à cocher Conserver les méta-informations du site Web pour une mise à jour ultérieure ou une réinstallation des extensions serveur FrontPage.

  3. Cliquez sur OK.

 

HAUT

Contrôle et correction des extensions serveur FrontPage sur un site ou sous-site

Il peut arriver qu'un auteur de site puisse ne pas réussir à télécharger le contenu d'un site, modifier le site en direct sur l'ordinateur serveur ou effectuer d'autres opérations d'auteur gérées par les extensions serveur FrontPage. Les causes du problème peuvent aller de la suppression ou du changement de nom accidentel de fichiers essentiels à la corruption des listes de contrôle d'accès (ACL). De nombreux problèmes liés aux opérations d'auteur peuvent être résolus par la commande Vérifie les extensions serveur qui effectue les opérations suivantes :

  • Contrôle les autorisations de lecture.
  • Contrôle que Service.cnf et Service.lck sont accessibles en lecture/écriture.
  • Met à jour Postinfo.html et _vti_inf.htm.
  • Vérifie que _vti_pvt, _vti_log et _vti_bin sont installés et que _vti_bin est exécutable.
  • Détermine si les racines du serveur virtuel ou les paramètres de métabase sont corrects et à jour.
  • Contrôle que le compte anonyme IUSR ne possède pas un accès en écriture.
  • Vous met en garde si vous utilisez un système de fichiers FAT, ce qui signifie que vous ne pouvez doter le site d'aucune sécurité (si vous utilisez IIS).

 

  1. Dans l'arborescence de la console, cliquez avec le bouton droit sur le site dont vous voulez contrôler et corriger les extensions serveur.

    Le site est contrôlé et corrigé ainsi que tous ses sous-sites.

  2. Cliquez sur Tâches dans le menu contextuel, puis sur Vérifie les extensions serveur.

    La fenêtre Vérifier le site Web affiche un journal d'état pour chaque site contrôlé.

Mise à niveau des extensions serveur FrontPage sur un site

Une nouvelle version des extensions serveur FrontPage sort régulièrement sur le marché. La nouvelle version fournit un support toujours plus grand aux auteurs et administrateurs de site ou corrige les fonctions de support actuelles, tout en continuant à prendre en charge les fonctions existantes de FrontPage, comme le compteur d'accès. Pour tirer avantage de ce nouveau support, vous devez commencer par installer la dernière version des extensions serveur sur l'ordinateur serveur, puis mettre à niveau un site FrontPage étendu avec cette version. Vous ne pouvez effectuer la mise à niveau des extensions serveur que sur les sites racine, cependant la mise à niveau d'un site Web racine actualise tous ses sous-sites.

  1. Dans l'arborescence de la console, cliquez avec le bouton droit sur le site Web racine dont vous voulez mettre à niveau les extensions serveur.
  2. Cliquez sur Tâches dans le menu contextuel, puis sur Extensions mises à niveau.

 

La commande Extensions mises à niveau est uniquement affichée lorsqu'une nouvelle version des extensions serveur est disponible. Pour mettre à niveau les extensions serveur FrontPage de tous les sites Web racine sur un ordinateur, cliquez avec le bouton droit de la souris sur Poste de travail dans l'arborescence de la console.

 

HAUT

Suppression d'un sous-site

Un sous-site Web peut devenir obsolète, rarement utilisé, ou pour une raison ou pour une autre, inutile. Par exemple, un projet dont les informations ont été publiées sur un intranet de société est terminé ou a été réorganisé. Ou bien un abonné ayant posté un site Web vers le serveur Web d'un fournisseur d'accès a mis fin à son abonnement. Dans ce type de situation ou d'autres, vous aurez peut-être besoin de supprimer le sous-site.

Lorsque vous supprimez un sous-site, vous supprimez l'ensemble de son contenu, ses fichiers, dossiers et sous-sites imbriqués ainsi que ses extensions FrontPage. Vous ne pouvez pas annuler la suppression d'un sous-site Web.

  1. Dans l'arborescence de la console, cliquez avec le bouton droit sur le sous-site que vous souhaitez supprimer, puis cliquez sur Supprimer le site Web doté des extensions serveur.
  2. Cliquez sur OK.

 

Si vous n'avez pas l'autorisation de supprimer un sous-site imbriqué sous le sous-site que vous supprimez, le sous-site imbriqué ne sera pas supprimé.

Conversion d'un dossier de site Web en sous-site Web

Si vous décidez qu'un dossier contient suffisamment de contenu Web (pages Web et graphiques) pour constituer lui-même un site Web, vous pouvez aisément convertir ce dossier en site Web FrontPage étendu. C'est en fait l'une des méthodes pour créer un sous-site.

  1. Dans l'arborescence de la console, cliquez avec le bouton droit sur le dossier que vous voulez convertir en sous-site FrontPage étendu.
  2. Cliquez sur Tâches dans le menu contextuel, puis sur Configurer les extensions serveur.

    S'il ne s'agit pas d'un serveur Web IIS version 4.0 ou ultérieure, cliquez sur Tâches dans le menu contextuel, puis sur Convertir un répertoire en site Web.

 

HAUT

Conversion d'un sous-site Web en dossier

Il se peut que vous décidiez qu'un sous-site n'est plus nécessaire, mais que vous souhaitiez néanmoins conserver son contenu. Dans ce cas, vous pouvez convertir un sous-site FrontPage étendu en dossier de son site Web parent. Lorsque vous convertissez un sous-site en dossier, les extensions serveur FrontPage sont supprimées du sous-site, ce dernier est converti en dossier standard du site Web parent, et les sous-sites Web imbriqués dans le sous-site converti sont liés aux sites Web parents appropriés.

Les sous-sites du sous-site Web converti peuvent acquérir des définitions de thèmes et de paramètres différentes. Si le sous-site Web converti ne comporte pas de sous-site converti, les pages contenues dans le sous-site converti risquent de perdre certaines propriétés de site Web.

  1. Dans l'arborescence de la console, cliquez avec le bouton droit sur le sous-site FrontPage étendu que vous souhaitez convertir en dossier.
  2. Cliquez sur Tâches dans le menu contextuel, puis sur Convertir un site Web avec des extensions serveur en un répertoire.

    3. Si le serveur Web n'est pas IIS, cliquez sur Tâches dans le menu contextuel, puis sur Convertir un site Web en un répertoire.

 

HAUT

Ouverture d'un site Web avec FrontPage

En tant qu'administrateur, vous devrez peut être modifier le thème, le texte, les graphiques ou d'autres éléments du site Web ou du sous-site. Si FrontPage est installé sur le même serveur que le site racine ou le sous-site Web, vous pouvez ouvrir le site directement à partir de la console et modifier son contenu ou effectuer d'autres opérations dans FrontPage. Ceci n'est pas possible autrement.

  1. Dans l'arborescence de la console, cliquez avec le bouton droit de la souris sur le site que vous voulez ouvrir dans FrontPage.
  2. Cliquez sur Tâches dans le menu contextuel, puis cliquez sur Ouvrir avec FrontPage.
  3. Sous FrontPage, modifiez le contenu du site Web et enregistrez vos modifications.

 

Si FrontPage n'est pas installé sur l'ordinateur serveur, la commande Ouvrir avec FrontPage n'apparaît pas.

 

HAUT

Recalcul de tous les liens hypertexte d'un site Web

Tout changement de la structure d'un site peut modifier les liens entre les différentes parties de ce site. Par exemple, si une page est ajoutée, renommée ou déplacée d'un dossier vers un autre, les liens hypertexte à cette page contenus dans tout autre page et document du site devront être mis à jour ou recalculés, pour rétablir les liens logiques. FrontPage recalcule automatiquement les liens hypertexte. Si, toutefois, vous souhaitez lancer manuellement un recalcul, vous pouvez le faire.

  1. Dans l'arborescence de la console, cliquez avec le bouton droit de la souris sur le site Web dont vous voulez recalculer les liens hypertexte.
  2. Cliquez sur Tâche dans le menu contextuel, puis sur l'onglet Recalculer le site Web.

 

HAUT

Choix du langage de script généré par défaut

En réponse à certaines opérations d'auteur, les extensions serveur FrontPage génèrent des scripts côté client. Par défaut, les extensions serveur génèrent ces scripts dans le langage de script JavaScript. JavaScript est reconnu par les deux navigateurs Web les plus courants, Netscape Navigator et Microsoft Internet Explorer, entre autres. Vous pouvez également choisir de générer des scripts en VBScript, qui n'est pas reconnu par Netscape Navigator. Vous pouvez néanmoins choisir VBScript si, par exemple, vous administrez un intranet de société fonctionnant exclusivement avec Internet Explorer ou si VBScript est le langage de script utilisé par le personnel technique de votre société.

  1. Dans l'arborescence de la console, cliquez avec le bouton droit de la souris sur le dossier pour lequel vous voulez définir le langage de script généré par défaut.
  2. Cliquez sur Propriétés dans le menu contextuel, puis sur l'onglet Extensions serveur.
  3. Dans la zone Script de client, sélectionnez un langage de script.

Définition manuelle des autorisations

L'autorisation en fonction du rôle que vous pouvez définir et gérer avec FrontPage sur chaque site pour les administrateurs, les auteurs et les visiteurs de sites peut ne pas toujours convenir à vos besoins. À titre d'exemple, vous souhaiterez peut-être définir des autorisations sur des fichiers et des dossiers. Vous pouvez manuellement définir des autorisations personnalisées dans les listes de contrôle d'accès (ACL). Pour plus d'informations sur la définition d'autorisations personnalisées, voir Kit de ressources des extensions serveur à l'adresse http://www.microsoft.com/france/frontpage/programmeIAP/comment.htm

Si néanmoins, vous utilisez FrontPage pour définir des autorisations, ce dernier modifie les autorisations personnalisées que vous avez définies en reconfigurant les ACL. Pour être certain que personne n'annule accidentellement les autorisations définies manuellement, vous pouvez désactiver les autorisations dans FrontPage.

  1. Dans l'arborescence de la console, cliquez sur le site racine pour lequel vous voulez modifier les autorisations manuellement.
  2. Cliquez sur Propriétés dans le menu contextuel, puis sur l'onglet Extensions serveur.
  3. Assurez-vous que la case à cocher Gérer les autorisations manuellement est activée.

 

HAUT

Activation et désactivation des opérations d'auteur sur un site Web racine et ses sous-sites.

Les sites Web en cours d'élaboration ou nécessitant des mises à jour fréquentes doivent être accessibles à leurs auteurs. Mais certains sites, une fois terminés, peuvent contenir des informations essentielles ou permanentes qui doivent rester inchangées. Il se peut aussi que vous souhaitiez empêcher d'autres personnes de modifier un site Web pendant que vous le déplacez vers un autre emplacement ou effectuez d'autres modifications. Pour protéger les informations d'un site, vous pouvez désactiver les opérations d'auteur de telle sorte que les utilisateurs ne puissent ni ajouter des données, ni modifier le contenu du site.

  1. Dans l'arborescence de la console, cliquez avec le bouton droit de la souris sur le site Web racine pour lequel vous voulez activer ou désactiver les opérations d'auteur.
  2. Cliquez sur Propriétés dans le menu contextuel, puis sur l'onglet Extensions serveur.
  3. Pour activer les opérations d'auteur, assurez-vous que la case à cocher Activer les opérations d'auteur est activée.

    Pour désactiver les opérations d'auteur, vérifiez que la case à cocher Activer les opérations d'auteur est désactivée.

 

HAUT

Possibilité ou non pour un dossier de contenir des scripts ou programmes exécutables

Lorsqu'un auteur de site veut inclure dans un site Web un script CGI ou une page ASP, comment pouvez-vous être sûr qu'il ne télécharge pas sans le savoir un programme contenant des erreurs ou — pire — un virus sur votre serveur Web ? Vous pouvez éviter les risques associés aux bogues et aux virus en interdisant aux auteurs de télécharger des scripts et des programmes dans un dossier inclus dans un site.

  1. Dans l'arborescence de la console, cliquez avec le bouton droit de la souris sur le site Web racine pour lequel vous souhaitez rendre les dossiers exécutables.
  2. Cliquez sur Propriétés dans le menu contextuel, puis sur l'onglet Extensions serveur.
  3. Pour faire en sorte qu'un dossier puisse contenir des scripts ou des programmes exécutables, assurez-vous que la case Autoriser les auteurs à télécharger des exécutables est sélectionnée.

    Pour éviter qu'un dossier puisse contenir des scripts ou des programmes exécutables, assurez-vous que la case Autoriser les auteurs à télécharger des exécutables est désélectionnée.

Journalisation des opérations d'auteur

Les utilisateurs ayant l'autorisation de modifier le contenu d'un site Web peuvent changer le texte, les graphiques, les liens, la structure et ainsi de suite. Pour conserver la trace des changements effectués sur un site et savoir qui a modifié quels fichiers, vous pouvez journaliser les opérations d'auteur réalisées dans un site racine et dans tous ses sous-sites. Le système enregistre alors l'heure à laquelle l'opération d'auteur a été effectuée, le nom d'utilisateur de l'auteur, le nom du site Web, l'hôte distant, les données opération par opération, puis il stocke ces informations dans un fichier journal appelé _vti_log/Author.log, dans le site Web racine. S'il y a un problème de sécurité, vous pouvez analyser ce fichier journal poue déterminer quel opération a été effectuée sur le site Web.

  1. Dans l'arborescence de la console, cliquez avec le bouton droit de la souris sur le site racine pour lequel vous souhaitez journaliser les opérations d'auteur.
  2. Cliquez sur Propriétés dans le menu contextuel, puis sur l'onglet Extensions serveur.
  3. Assurez-vous que la case à cocher Journaliser les actions d'auteur est activée.

 

HAUT

Exigence de SSL (Secure Sockets Layer) pour les opérations d'auteur

Les informations Web sont le plus susceptibles d'être interceptées pendant qu'elles se trouvent « dans le tuyau »  —  c'est-à-dire en route entre une partie du Web et l'autre. Vous pouvez renforcer de façon significative la sécurité du pipeline contre les pirates en exigeant la norme SSL (Secure Sockets Layer) pour la transmission d'informations entre FrontPage, les navigateurs Web et les serveurs Web.

  1. Dans l'arborescence de la console, cliquez avec le bouton droit de la souris sur le site racine pour lequel vous voulez utiliseer SSL.
  2. Cliquez sur Propriétés dans le menu contextuel, puis sur l'onglet Extensions serveur.
  3. Assurez-vous que la case à cocher Exiger SSL pour les opérations d'auteur est activée.

 

Si vous exigez SSL pour les opérations d'auteur, les auteurs qui tentent de travailler sur le site Web obtiennent un message indiquant qu'ils doivent utiliser SSL, accessible sous FrontPage.

Réglage des performances du site

La rapidité avec laquelle un site Web répond à une demande émanant d'un client FrontPage dépend largement de la taille du site, notamment du nombre de pages et d'autres fichiers qu'il contient. Vous pouvez améliorer le temps de réponse d'un site en le « réglant ». Lorsque vous réglez un site Web, les extensions serveur FrontPage mettent de côté une certaine quantité de cache pour le site Web, en fonction du nombre de pages Web. À titre d'exemple, vous pouvez régler un site Web pour moins de 100 pages ou plus de 1 000. Vous pouvez, d'autre part, personnaliser la taille du cache ainsi que la taille d'index pour une recherche de texte intégrale.

  1. Dans l'arborescence de la console, cliquez avec le bouton droit de la souris sur les performances du site Web que vous souhaitez adapter.
  2. Cliquez sur Propriétés dans le menu contextuel, puis sur l'onglet Extensions serveur.
  3. Dans la zone Performance, sélectionnez la fourchette de pages la plus proche du nombre réel de pages contenu dans le site Web que vous réglez.
  4. Pour personnaliser les performances du site, cliquez sur Utiliser les paramètres personnalisés, puis entrez les tailles voulues pour le cache et l'index de recherche de texte intégrale.

Activation du contrôle de source

Lorsque plusieurs personnes modifient le contenu du site Web, vous pouvez utiliser le contrôle de source pour savoir qui modifie actuellement un document Web particulier, pour identifier toute modification, et empêcher que les modifications effectuées par un auteur ne soient effacées par celles d'un autre, et pour revenir à une version antérieure d'un document, si nécessaire. Pour offrir un contrôle de source pour un site Web particulier, vous pouvez choisir le contrôle de source FrontPage intégré ou utiliser un programme de contrôle de source prenant en charge FrontPage, tel que Microsoft® Visual SourceSafe™.

Le contrôle de source intégré est inclus dans les extensions serveur FrontPage. Vous pouvez l'utiliser pour extraire et archiver un site Web et pour revenir à la dernière version enregistrée du site. Visual SourceSafe et d'autres programmes de contrôle de source doivent être achetés séparément et installés sur votre ordinateur. Ces programmes effectuent les mêmes opérations que le contrôle de source intégré, mais en outre, ils assurent le suivi des modifications et peuvent revenir à différentes versions antérieures d'un site Web.

  1. Dans l'arborescence de la console, cliquez avec le bouton droit sur le site Web pour lequel vous voulez activer le contrôle de source.
  2. Cliquez sur Propriétés dans le menu contextuel, puis sur l'onglet Extensions serveur.
  3. Dans la zone Contrôle de version, sélectionnez Usage externe ou Utiliser le contrôle de version standard.
  4. Si vous avez sélectionné Usage externe, entrez le nom du projet Visual SourceSafe ou d'un autre que vous souhaitez utiliser.

 

Vous ne pouvez utiliser Visual SourceSafe avec FrontPage que si l'option Activer l'intégration Visual SourceSafe est activée dans Visual SourceSafe. C'est une option d'installation personnalisée que vous devez sélectionner lors de l'installation de Visual SourceSafe.

 

HAUT

Configuration des options de messagerie

Certaines fonctions nécessitent l'envoi de courrier électronique aux visiteurs qui parcourent le site Web, tel un programme de traitement des formulaires de courrier électronique. Pour activer ces fonctions pour l'envoi de courrier électronique, vous devez préciser l'adresse de messagerie du serveur Web, une adresse de contact, un hôte SMTP, un schéma d'encodage de courrier et un jeu de caractères de courrier.

  1. Dans l'arborescence de la console, cliquez avec le bouton droit sur le site racine pour lequel vous voulez définir des options de messagerie.
  2. Cliquez sur Propriétés dans le menu contextuel, puis sur l'onglet Extensions serveur.
  3. Dans la zone Options, cliquez sur Paramètres.
  4. Entrez les paramètres de votre choix.
