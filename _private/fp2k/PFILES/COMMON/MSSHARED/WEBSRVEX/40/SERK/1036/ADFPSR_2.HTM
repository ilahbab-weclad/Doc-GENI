Commande Install

Cette commande installe les extensions serveur FrontPage sur le port spécifié d'un serveur virtuel en utilisant le nom d'administrateur et le mot de passe indiqués. Si NomSite est précisé, les extensions serveur sont installées sur le sous-site indiqué. Si aucun nom de site n'est spécifié, les extensions serveur sont installées sur le site racine du serveur virtuel indiqué. Pour tout type de serveur excepté website et msiis, vous devez préciser un fichier de configuration serveur.

Syntaxe

fpsrvadm.exe -o install -p nnnn -m NomHôte -u NomUtilisateur -pw motdepasse
    -t TypeServeur [-s FichierConfigServeur] [ -xu NomUtilisateurUNIX]
    [ -xg NomGroupeUNIX] [ -n yes]

Sous IIS

Pour installer les extensions serveur sous Windows NT avec un serveur Web IIS, utilisez les arguments suivants.

fpsrvadm.exe -o install -t msiis -p 80 -m sample.microsoft.com -u AdminAccount

L'argument password n'est pas nécessaire car sous IIS, les mots de passe des comptes sont spécifiés dans les outils d'administration de la liste de comptes Windows NT, non pas sur le serveur Web ou dans les outils d'administration de FrontPage.

Sous UNIX

Si l'argument -xu est spécifié, le contenu du site et le propriétaire des programmes de remplacement des extensions serveur FrontPage sont modifiés (commande chown) en NomUtilisateurUNIX.

Si l'argument -xg est utilisé, le contenu du site et les programmes de remplacement des extensions serveur FrontPage changent de propriétaire pour devenir propriété de groupe du NomGroupeUNIX spécifié. Remarquez que vous pouvez utiliser l'argument -xu sans l'argument -xg.

Si -xu ou -xg est précisé, les programmes de remplacement des extensions serveur sont accessibles en lecture/écriture et le bit de définition de l'identificateur d'utilisateur correspond au nom d'utilisateur et au nom de groupe indiqués. Remarquez que seuls les programmes de remplacement des extensions serveur font l'objet de modifications de leurs conditions d'accès (chmode), pas les fichiers de contenu de site.

Si -xu ou -xg est précisé, vous pouvez utiliser l'argument -[n yes] pour indiquer que seuls les répertoires et les programmes de remplacement des extensions serveur créés par FrontPage doivent changer de propriétaire (chown), et non pas les fichiers de contenu.

Avec le correctif logiciel Apache pour FrontPage

Pour installer les extensions serveur sur un serveur Web Apache sur lequel le correctif logiciel FrontPage pour Apache est installé, utilisez la ligne de commande ci-après :

fpsrvadm.exe -o install -t apache-fp -s /usr/local/apache/conf/httpd.conf -p 80 -m sample.microsoft.com -u AdminAccount -pw AdminPassword -xu www -xg www

Commande Upgrade

Cette commande met à jour les extensions serveur FrontPage sur le port nnnn du serveur virtuel NomHôte. Les extensions serveur sont mises à jour sur le site racine du serveur virtuel spécifié, et les sous-sites du site racine sont également mis à jour.

Syntaxe

fpsrvadm.exe -o upgrade -p nnnn -m NomHôte
    [ -xu NomUtilisateurUNIX] [ -xg NomGroupeUNIX] [ -n yes]

Sous UNIX

Si -xu et -xg sont précisés, le propriétaire et le mode des répertoires et des fichiers d'extensions serveur créés par FrontPage sont modifiés en NomUtilisateurUNIX et NomGroupeUNIX. L'argument -n précise que ce changement de propriétaire et de mode ne concerne que les répertoires et les fichiers d'extension serveur créés par FrontPage.

Arguments de ligne de commande Fpsrvadm

HAUT

Commande Uninstall

Cette commande désinstalle les extensions serveur FrontPage sur le port nnnn du serveur virtuel NomHôte. Elle désinstalle également les extensions serveur des sous-sites du site racine.

Syntaxe

fpsrvadm.exe -o uninstall -p nnnn -m NomHôte

Remarques

Vous remarquerez que la désinstallation des extensions serveur FrontPage ne supprime pas le contenu, elle supprime seulement les programmes des fichiers d'extensions serveur et les fichiers d'extensions serveur accessoires.

Cette opération laisse suffisamment de méta-information FrontPage dans le contenu de chaque site pour ramener chaque site à son état précédent si les extensions serveur sont réinstallées. À titre d'exemple, les sous-sites présents au moment de la désinstallation des extensions serveur seront restaurés lors de leur réinstallation.

Arguments de ligne de commande Fpsrvadm

HAUT

Commande Fulluninstall

Cette commande désinstalle les extensions serveur FrontPage sur le port nnnn du serveur virtuel NomHôte. Elle désinstalle également les extensions serveur des sous-sites du site racine.

Syntaxe

fpsrvadm.exe -o fulluninstall -p nnnn -m NomHôte

Remarque

Cette commande désinstalle les extensions serveur sur le port et le serveur virtuel spécifiés. Si le site racine comporte des sous-sites, les extensions serveur FrontPage sont également désinstallées sur les sous-sites. Contrairement à la commande Uninstall, cette commande ne laisse pas d'informations spécifiques à FrontPage dans la zone de contenu du site. Lorsque Fulluninstall a été utilisée sur un serveur virtuel, les sous-sites ne peuvent pas être recréés automatiquement au moment de la réinstallation des extensions serveur FrontPage.

HAUT

Commande Create

Cette commande crée un sous-site FrontPage étendu sur le répertoire spécifié au sein d'un site Web FrontPage étendu.

Syntaxe

fpsrvadm.exe -o create -p nnnn -m NomHôte -w NomSite [-u NomUtilisateur] [-pw motdepasse]
 [ -xu NomUtilisateurUNIX] [ -xg NomGroupeUNIX] [ -n> yes]

Remarques

Pour NomSite, indiquez le chemin du répertoire racine de la zone de contenu au sous-site que vous créez. L'argument -pw motdepasse n'est pas nécessaire sur les serveurs IIS.

Si les arguments NomUtilisateur et motdepasse ne sont pas fournis, les paramètres de sécurité des nouveaux sous-sites sont hérités du site racine. Si ces arguments sont précisés, le nouveau sous-site dispose d'autorisations uniques avec un compte administrateur initial basé sur NomUtilisateur et motdepasse.

Arguments de ligne de commande Fpsrvadm

HAUT

Commande Merge

Cette commande désinstalle les extensions serveur sur le sous-site spécifié ainsi que sur tous ses sous-sites. Elle convertit le sous-site en dossier de son site FrontPage étendu parent.

Syntaxe

fpsrvadm.exe -o merge -w NomSite -p nnnn -m NomHôte

Remarques

Pour NomSite, indiquez le chemin d'accès du répertoire racine de la zone de contenu au sous-site que vous fusionnez.

Arguments de ligne de commande Fpsrvadm

HAUT

Commande Check

Cette commande contrôle et corrige l'installation des extensions serveur FrontPage sur le port nnnn du serveur virtuel NomHôte. Si NomSite est précisé, les extensions serveur sont contrôlées sur le sous-site indiqué. Sinon, les extensions serveur sont contrôlées sur le site racine du serveur virtuel spécifié. Si le site que vous contrôlez comporte des sous-sites, ces derniers sont également vérifiés.

Le contrôle des extensions serveur FrontPage englobe les opérations suivantes :

  • Contrôler les autorisations sur les DLL ou les exécutables des extensions serveur FrontPage.

  • Vérifier l'existence et l'exactitude des répertoires _vti_bin , _vti_pvt, _vti_log, etc. créés par FrontPage.

  • Vérifier que les racines du serveur virtuel sont correctes et à jour.

  • Vérifier que les paramètres de métabase sont corrects et à jour. (Les métabases sont des structures de stockage pour les paramètres de configuration IIS.)

  • Contrôler que les DLL ou exécutables de remplacement de _vti_bin ne sont pas corrompus.

  • Contrôler que les autres DLL ou exécutables ne sont pas corrompus.

Syntaxe

fpsrvadm.exe -o check -p nnnn -m NomHôte [ -w NomSite ]

Remarques

Le contrôle des extensions serveur englobe le remplacement des répertoires manquants et des fichiers créés par FrontPage ainsi que la vérification que tous les exécutables créés par FrontPage sont présents et configurés avec les autorisations adéquates.

Arguments de ligne de commande Fpsrvadm

HAUT

Commande Security

Cette commande permet de définir les autorisations de site Web FrontPage étendu pour le site FrontPage étendu NomSite, sur le serveur virtuel et le port spécifiés, pour le nom d'utilisateur et le mot de passe indiqués. Si NomSite est le site racine, utilisez une barre oblique (/) pour le préciser.

Syntaxe

fpsrvadm.exe -o security -p nnnn -m NomHôte -w NomSite
    -a TypeAccès -u NomUtilisateur -pw motdepasse [-i AdresseIP]

Remarques

Pour ajouter un administrateur, précisez le type d'accès administrateurs. Pour ajouter un auteur, indiquez le type d'accès auteurs, et pour ajouter un visiteur de site, précisez le type d'accès utilisateurs. Pour supprimer les autorisations de site, indiquez le type d'accès supprimer. Pour réduire les autorisations octroyées à un compte, vous devez d'abord supprimer le compte puis l'ajouter à nouveau avec le nouveau niveau d'autorisations.

Utilisez l'argument facultatif -i pour limiter les opérations d'auteur, l'administration ou l'accès des ordinateurs client au site en tant que visiteur, selon les adresses IP des ordinateurs. Vous pouvez utiliser un astérisque (*) comme caractère générique à n'importe quel emplacement des quatre sections d'adresse IP. Par exemple, le masque d'adresse IP 157.*.*.* désigne toute adresse IP commençant par 157. Notez que les limitations d'adresses IP ne sont pas gérées par certains types de serveurs pris en charge par les extensions serveur FrontPage.

Sous IIS

Sur les serveurs Microsoft IIS, le nom d'utilisateur doit être un compte Windows NT. Le mot de passe est ignoré s'il est fourni.

HAUT

Commande Chown

Sous UNIX seulement. Cette commande change le propriétaire des répertoires et des programmes de remplacement des extensions serveur créés par FrontPage, en même temps que le contenu du site. La commande chown configure également le bit de définition de l'identificateur d'utilisateur dans les exécutables des extensions serveur FrontPage, au sein d'un site Web FrontPage étendu. Utilisez-la pour renforcer la sécurité.

Syntaxe

fpsrvadm.exe -o chown -p nnnn -m NomHôte [ -w NomSite ]
    [ -xu NomUtilisateurUNIX] [ -xg NomGroupeUNIX] [ -n yes]

Sous UNIX

Si NomSite est spécifié, les extensions serveur deviennent la propriété du sous-site nommé. Sinon, elles deviennent la propriété du site racine.

Si -xu est spécifié, le contenu du site Web étendu et les programmes de remplacement des extensions serveur FrontPage deviennent la propriété de NomUtilisateurUNIX.

Si -xg est spécifié, le contenu du site Web étendu et les programmes de remplacement des extensions serveur FrontPage deviennent la propriété du groupe NomGroupeUNIX.

Si -xu ou -xg est spécifié, les programmes de remplacement des extensions serveur sont configurés pour un accès en lecture/écriture et le bit de définition de l'identificateur utilisateur désigne le nom de l'utilisateur et le groupe indiqués. Notez que seuls les programmes de remplacement changent de mode, non pas les fichiers de contenu du site.

L'argument -n indique que seuls les répertoires et les programmes de remplacement des extensions serveur créés par FrontPage peuvent changer de mode, pas les fichiers de contenu.

Commande Enable

Cette commande autorise les opérations d'auteur et d'administration sur les sites Web FrontPage étendus par l'intermédiaire du client FrontPage sur le port nnnn du serveur virtuel NomHôte.

Syntaxe

fpsrvadm.exe -o enable -p nnnn -m NomHôte

Arguments de ligne de commande Fpsrvadm

HAUT

Commande Disable

Cette commande interdit les opérations d'auteur et d'administration sur les sites Web FrontPage étendus par l'intermédiaire du client FrontPage sur le port nnnn du serveur virtuel NomHôte.

Syntaxe

fpsrvadm.exe -o disable -p nnnn -m NomHôte

Arguments de ligne de commande Fpsrvadm

HAUT

Commande Recalc

Cette commande synchronise les bases de données de contenu FrontPage avec l'état actuel du site. Elle recalcule et corrige tous les liens hypertexte du site FrontPage étendu sur le serveur virtuel et le port spécifiés. Elle réintègre les pages des composants Insertion de pages, recalcule d'autres composants (comme les formulaires de recherche et les barres de navigation), réapplique des bordures aux pages qui en utilisent, redéfinit les autorisations dans les pages de résultats du programme de traitement des formulaires FrontPage, réindexe les catégories et recalcule les index de texte.

Syntaxe

fpsrvadm.exe -o recalc -p nnnn -m NomHôte -w NomSite

Remarques

Si NomSite est le site racine, utilisez une barre oblique (/) pour le préciser.

Arguments de ligne de commande Fpsrvadm

HAUT

Commande Putfile

Cette commande importe le fichier nomfichier comme fichier de destination dans le site Web FrontPage étendu NomSite sur le serveur et le port spécifiés.

Syntaxe

fpsrvadm.exe -o putfile -p nnnn -m NomHôte -w NomSite
    -f nomfichier -d destination

Remarques

L'argument destination doit être l'URL du fichier de destination, par rapport au dossier de premier niveau du site. Si NomSite est le site racine, utilisez une barre oblique (/) pour le préciser.

Arguments de ligne de commande Fpsrvadm

HAUT

Commande Recalcfile

Cette commande recalcule et répare tous les liens hypertexte internes de l'URL de destination spécifiée dans le site Web FrontPage étendu NomSite sur le serveur virtuel et le port spécifiés. Elle réintègre également les pages dans les composants Insertion de pages et recalcule les index de texte.

Syntaxe

fpsrvadm.exe -o recalcfile -p nnnn -m NomHôte -w NomSite
    -d destination

Remarques

L'argument destination doit être l'URL du fichier de destination, par rapport au dossier de premier niveau du site. Si NomSite est le site racine, utilisez une barre oblique (/) pour le préciser.

Arguments de ligne de commande Fpsrvadm

HAUT

Commande Delete

Cette commande supprime le sous-site NomSite sur le serveur virtuel et le port spécifiés. Elle ne permet pas de supprimer le site racine. Pour ce faire, utilisez la commande Uninstall.

Cette commande supprime la totalité du contenu, y compris tous les sous-sites du sous-site spécifié.

Syntaxe

fpsrvadm.exe -o delete -p nnnn -w NomSite [-m NomHôte]

Sous UNIX

Cette commande est le seul moyen de supprimer des sous-sites sur les serveurs Web NCSA, Stronghold et Apache. Vous ne pouvez pas utiliser le client FrontPage pour supprimer des sous-sites sur ces serveurs.

Arguments de ligne de commande Fpsrvadm

HAUT

Commande Rename

Cette commande renomme le sous-site NomSite sur le serveur virtuel et le port spécifiés et lui affecte le nouveau nom de site, destination.

Syntaxe

fpsrvadm.exe -o rename -p nnnn -w NomSite -d destination [-m NomHôte]

Sous UNIX

Cette commande est le moyen de renommer des sous-sites sur des serveurs Web NCSA, Stronghold et Apache. Vous ne pouvez pas utiliser le client FrontPage pour renommer des sous-sites sur ces serveurs.

Remarques

L'argument destination doit désigner le nouvel URL du sous-site, par rapport au site racine.

Arguments de ligne de commande Fpsrvadm

HAUT

Commande Setdirexec

Cette commande précise que le répertoire destination peut contenir des programmes exécutables dans le site Web FrontPage étendu NomSite sur le serveur virtuel et le port spécifiés.

Syntaxe

fpsrvadm.exe -o setdirexec -p nnnn -w NomSite -d destination
        [-m NomHôte]

Sous UNIX

Cette commande est le seul moyen de rendre exécutable un répertoire sur les serveurs Web NCSA, Stronghold et Apache. Vous ne pouvez pas utiliser le client FrontPage pour rendre un répertoire exécutable sur ces serveurs.

Remarques

L'argument destination doit désigner l'URL du dossier de destination, par rapport au dossier de premier niveau du site. Si NomSite correspond au répertoire racine, utilisez une barre oblique (/) pour le préciser.

Arguments de ligne de commande Fpsrvadm

HAUT

Commande Setdirnoexec

Cette commande précise que le répertoire destination ne peut pas contenir de programmes exécutables dans le site Web FrontPage étendu NomSite sur le serveur virtuel et le port spécifiés.

Syntaxe

fpsrvadm.exe -o setdirnoexec -p nnnn -w NomSite -d destination
        [-m NomHôte]

Sous UNIX

Cette commande est le seul moyen de rendre un répertoire non exécutable sur des serveurs Web NCSA, Stronghold et Apache. Vous ne pouvez pas utiliser le client FrontPage pour rendre un répertoire non exécutable sur ces serveurs.

Remarques

L'argument destination doit désigner l'URL du dossier de destination, par rapport au dossier de premier niveau du site. Si NomSite est le site racine, utilisez une barre oblique (/) pour le préciser.
